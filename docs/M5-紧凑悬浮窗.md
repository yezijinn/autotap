# 精灵点击器 M5 设计规格：紧凑悬浮窗体系（浮层化重构）

> 包名 `com.auto.fairy`，技术栈 **Views + ViewBinding + AppCompat**，沿用 M2 / M4 视觉规范（配色 / 间距 / 圆角 / 字号 / 图标全部复用），**不引入 Compose、不引入 Material、不新增依赖**。
> 本文件面向 `@fixer`：覆盖 M2 §3 旧「折叠球 + 200dp 展开面板」设计。所有布局均为可直接落地的 `res/layout/*.xml` 规格，含 view id 命名规范、drawable / strings / dimens 追加清单与控制器改造要点。
> **核心目标（最高优先级，覆盖旧设计）**：① 悬浮窗尽可能小，只保留 开始/暂停、停止、编辑 三个操作；② 所有操作都用可移动悬浮窗完成，不用 App 全屏页；③ 保留必要的状态反馈（运行中/已暂停/就绪/出错）与最小信息（当前脚本名 / 循环次数）。

## 1. 紧凑悬浮窗（核心）

### 1.1 设计原则

- **折叠态 = 单球**：直径由 §1.3 决定（推荐 48dp），背景为状态色椭圆（代码 `backgroundTint`），中心放一个 **播放/暂停切换图标**（仅作状态指示：运行中显示暂停图标、其余显示播放图标）。球本身只做两件事：**点按 → 展开面板**，**拖动 → 移动位置**。
- **展开态 = 极小面板**：宽度固定 `overlay_panel_w = 160dp`，只放 **三个按钮**（开始/暂停切换、停止、编辑）+ **一行最小信息**（脚本名截断 + 循环 `∞·N` 或 `N/M`）。不再有「打开列表」整块文字按钮、不再有独立状态大标题、不再有步骤进度行——这些都已移除或下沉到球色与信息行。
- **状态反馈靠球色 + 极小角标**：运行中绿 / 暂停橙 / 就绪灰 / 出错红 / 后端失效红。信息行只承载「脚本名 + 循环」，状态由球色表达，避免重复文案浪费空间。

### 1.2 折叠态 / 展开态切换

沿用 M2 的 `visibility` 切换思路，但手柄与文案大幅瘦身：

```
折叠态（overlay_collapsed，单球）
   └─ 点按 → 展开态（overlay_expanded，160dp 面板）

展开态（overlay_expanded）
   ├─ 顶部手柄条 overlay_handle：拖动移动；点按 → 折叠回球
   ├─ 信息行：text_overlay_name（截断） + text_overlay_loop（药丸）
   └─ 三按钮行：btn_overlay_toggle / btn_overlay_stop / btn_overlay_edit
```

> 拖动/点按区分阈值沿用 `DRAG_SLOP_DP = 8`（见 M2 §3.1 / OverlayController 既有常量），边缘吸附沿用 `SCREEN_MARGIN_DP = 8`。展开面板整体也可拖动——把 `dragListener` 同时挂在 `overlay_handle` 上即可（按钮各自 `onClick`，不在拖动手柄内，互不吞事件）。

### 1.3 三种尺寸候选（折叠球直径 + 展开面板宽度）

| 候选 | 折叠球直径 | 展开面板宽 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|---|
| A | **48dp** | 160dp | 候选里最小；48 ≥ 40 可点下限，图标 24dp 在 48 容器内留白舒适；面板 160dp 刚好放下三按钮 + 一行信息 | 极窄屏（320dp 逻辑宽）下面板占屏约一半 | **推荐**：最平衡 |
| B | 56dp | 160dp | 图标更大更醒目，误触更低 | 比 A 大 17%，紧凑度下降，小屏更挡内容 | 可选（大屏 / 老年模式） |
| C | 64dp | 160dp | 单手盲操作最稳 | 明显挡屏，违背「尽可能小」 | 不推荐，仅做对比基线 |

**推荐：候选 A（球 48dp，面板 160dp）。** 说明：M5 硬约束「靶面 ≥ 40dp」，48dp 是候选中唯一压在 40–44 可点下限之上又不过度的尺寸；若想在合规前提下更极致，可压到 **44dp**（M2 旧值），但 24dp 图标在 44 容器内边距仅 10dp，低 DPI 屏略挤，故取 48dp 为甜点。面板宽 160dp 是「三按钮（40×3 + 间距）+ 信息行」的最小合身宽度，再窄会挤换行。

### 1.4 状态色映射表（紧凑球）

| 播放状态 / 健康 | 折叠球颜色 | 折叠球中心图标 | 面板 `text_overlay_loop` 下方是否提示 |
|---|---|---|---|
| 运行 RUNNING | 绿 `status_running` | `ic_pause`（表示「可暂停」） | — |
| 暂停 PAUSED | 橙 `status_paused` | `ic_play` | — |
| 就绪 IDLE（空闲） | 灰 `status_stopped` | `ic_play` | — |
| 出错 ERROR（逻辑错，后端仍在） | 红 `status_error` | `ic_play` | Toast 已报错（沿用 M2） |
| 后端失效 Health.DEAD（无障碍被杀等） | 红 `status_error` | `ic_play` | `btn_overlay_toggle` 置灰（`isEnabled=false`，alpha 0.4） |

> 健康只有 ALIVE/DEAD 两档：ALIVE 不显示角标；DEAD 变红且禁用开始。

### 1.5 「编辑」按钮的衔接

点 `btn_overlay_edit` **不再启动 MainActivity**（旧 `openList()`），而是弹出 **浮层脚本列表**（`overlay_script_list.xml`，见 §2.a / §4.2）。从列表行的「编辑」图标再进入 **浮层编辑器**（§2.b / §4.3）。整条链路不离开悬浮层，符合「所有操作都用可移动悬浮窗完成」。

## 2. 浮层化改造清单（把全屏页改成浮层）

> 总原则：**常规操作全部浮层化**；只有「首次启动引导 / 权限 / 入口」这种一次性流程保留在 `MainActivity`。下面逐个评估。

### 2.a 脚本列表 → 浮层列表（必须）

- **布局**：`overlay_script_list.xml`（§4.2），宽 = 屏宽 90%（`WindowManager` 参数设，XML 内用 `match_parent`），最大宽 `overlay_list_max_w`；高 = 屏高 70%（参数设），内部 `RecyclerView` 滚动。
- **单行项**：`item_overlay_script_row.xml`（§4.4）—— 状态点 + 脚本名（截断）+ 循环·步数小字 + 三个图标按钮（播放 / 编辑 / 更多）。
- **底部操作条**：`btn_list_new`（新建脚本）+ `btn_list_record`（录制）。点击新建 → 启动 `ScriptEditorActivity`（浮层化，§2.b）；点击录制 → 启动 `RecordOverlay`（§2.e）。
- **交互**：顶部手柄条 `list_handle` 拖动移动；右上 `btn_list_close` 关闭；点行内「更多」(`ic_more`) 弹 `PopupMenus`（播放 / 编辑 / 导出 / 删除，复用 M2 `item_popup_menu` + `PopupMenus`）。
- **承载方式**：推荐用 `WindowManager` + `TYPE_APPLICATION_OVERLAY`（新增 `OverlayScriptList` 控制器，仿 `OverlayController`），与球同级、可拖动；数据直接读 `ScriptRepository`，不走 Activity。

### 2.b 脚本编辑器 → 浮层编辑器（必须，复用 M4）

- **方案（推荐，最小改动）**：保留 M4 的 `ScriptEditorActivity` 与 `activity_script_editor.xml` **完全不动**，仅把它的主题从全屏改为 **浮层 Dialog 主题**（`Theme.AppCompat.DayNight.Dialog` 或自定义透明主题），并在 `AndroidManifest.xml` 给该 Activity 加 `android:windowIsFloating` 风格：窗口宽 90% 屏宽、高 ≤ 70% 屏高（`windowSoftInputMode="adjustResize"` 保留，软键盘不顶破浮层）。
- **替代方案（WindowManager 壳）**：若不想用 Activity，可用 `overlay_script_editor.xml`（§4.3）由 `WindowManager` 承载——它是圆角卡片壳，内部直接放 M4 的编辑器内容（顶部栏 + 滚动主体 + 添加 FAB）。但该方案要重写 `ScriptEditorActivity` 为 View 控制器，工作量更大，**不推荐**，仅当 Activity 方案与现有保存/返回逻辑冲突时备选。
- **高度约束**：`≤ 70% 屏高` 由窗口参数保证；内部 `ScrollView` 可滚，步骤多也不溢出。
- **复用 M4 内部件**：步骤列表用 `item_step_card.xml`；步骤编辑用 `dialog_step_edit.xml`（tap/swipe/delay/loop 区块切换）；坐标块用 `block_coord_picker.xml`；时长用 `block_duration.xml`；添加步骤弹层用 `dialog_add_step.xml`。这些 **全部原样复用，不复制**。
- **从浮层列表进入**：列表行「编辑」→ `ScriptEditorActivity.intent(ctx, id)`，浮层化后自然盖在列表之上。

### 2.c 取坐标工具 → 保留全屏浮层（保留）

- `CoordinatePicker`（`overlay_coordinate_picker.xml`，`TYPE_APPLICATION_OVERLAY` 全屏）**保留不动**。
- **如何从浮层编辑器唤起**：编辑器内 `dialog_step_edit.xml` 的 `block_coord_picker` 中「取坐标」按钮 → 调用 `CoordinatePicker`（M4 既有逻辑）。因为编辑器现在是 Dialog Activity，picker 作为 `TYPE_APPLICATION_OVERLAY` 浮层天然盖在 Dialog 之上；进 picker 前隐藏控制球面板（避免两个 overlay 抢触摸，沿用 M4 §3.4.5 互斥规则），退出 picker 恢复。

### 2.d 坐标总览 → 浮层 Dialog 化（保留）

- M4 的 `overlay_coord_preview.xml` 本就是 `Dialog` + 透明主题（暗化全屏 + 大号屏幕矩形 + 点标记 + 关闭），**保留**。从浮层编辑器的「预览坐标」按钮唤起，依旧是 Dialog，不占全屏 Activity。

### 2.e 录制浮层 → 保留全屏（保留，理由充分）

- `RecordOverlay`（`overlay_record.xml`，全屏 `TYPE_APPLICATION_OVERLAY`，吃触摸）**必须保留全屏**，不能缩成小球：
  1. **必须独占触摸**：录制要捕获全屏手势坐标，透明触摸层 `record_touch_layer` 必须覆盖整屏并 `return true` 吃掉事件（M2 §4.1 / §7.4）。缩成小球无法捕获屏幕其余区域的触摸。
  2. **用户心智**：录制时底层 App 不可操作，全屏遮罩 + 顶部/底部操作条是最清晰的状态表达；小球方案会让用户误以为可继续操作底层。
  3. **与取坐标一致**：取坐标也是全屏吃触摸浮层，二者同属「全屏捕获」类，统一处理互斥最简单。
- 录制入口：浮层列表底部「录制」按钮，或编辑器内「录制」快捷。进入录制时隐藏控制球面板 + 列表 + 编辑器（§3 互斥表）。

### 2.f 诊断 / 保活 / 设置 → 浮层 Dialog（建议）

- **诊断 Diagnose**：改为 **浮层 Dialog**（宽 90%，高 ≤ 70%）。触发：① 球处于 DEAD 时，点 `btn_overlay_edit` 进列表后，行「更多」或列表头「更多」含「诊断」入口；② 也可从 `MainActivity` 入口进。展示后端健康、权限状态、一键修复。
- **保活 KeepAlive**：改为 **浮层 Dialog**（引导式，宽 90%）。展示厂商省电/后台限制白名单指引 + 一键跳转设置。一次性引导为主，平时不需要。
- **设置 Settings**：**可全屏或浮层**——推荐 **浮层 Dialog**（宽 90%，选项少：边缘吸附开关、循环默认、关于），与诊断/保活一致；若设置项将来变多，再升全屏 Activity 也不迟。
- 三者统一用 `Theme.AppCompat.DayNight.Dialog`，内容与 M2 的 `fragment_diagnose` / `fragment_keepalive` / `fragment_placeholder` 文案复用。

### 2.g MainActivity 角色重新定义

**降级为「首次启动引导 + 权限 + 入口」**，常规操作全部浮层。信息架构图：

```
精灵点击器
├─ MainActivity（首次启动 / 引导 / 权限 / 入口，平时几乎不用）
│   ├─ 首次启动：引导授予「无障碍服务」+「显示在其他应用上层」权限
│   ├─ 入口按钮：① 显示悬浮球（attach OverlayController） ② 打开脚本列表浮层 ③ 设置
│   └─ 诊断 / 保活 / 设置 的兜底容器（浮层 Dialog 失败时的退路）
│
├─ OverlayController        控制球 / 面板（常驻 TYPE_APPLICATION_OVERLAY，最小）
├─ OverlayScriptList        脚本列表浮层（TYPE_APPLICATION_OVERLAY，90%×70%）
├─ ScriptEditorActivity     编辑器浮层（Dialog 主题，90%×70%，复用 M4）
├─ CoordinatePicker         取坐标全屏浮层（TYPE_APPLICATION_OVERLAY，保留 M4）
├─ RecordOverlay            录制全屏浮层（TYPE_APPLICATION_OVERLAY，保留 M2）
└─ Diagnose/KeepAlive/Settings  浮层 Dialog（90%×70%）
```

> 常规播放/编辑/列表/取坐标/录制 **全程不启动 MainActivity 全屏页**；MainActivity 只在 App 首次冷启动或出现权限/引导需求时出现。

## 3. 多浮层共存与层级

### 3.1 同时可能存在的浮层

| 浮层 | 类型 | 触摸行为 |
|---|---|---|
| 控制球 / 面板 | `TYPE_APPLICATION_OVERLAY`，小 | `FLAG_NOT_FOCUSABLE`，只占小球区域，不抢焦点 |
| 脚本列表浮层 | `TYPE_APPLICATION_OVERLAY`，90%×70% | 浮层内可点；外部区域不拦截（透明留空） |
| 编辑器浮层 | Dialog Activity，90%×70% | 对话框内可点；外部遮罩点关 |
| 取坐标浮层 | `TYPE_APPLICATION_OVERLAY`，**全屏吃触摸** | 全屏捕获，吃掉底层触摸 |
| 录制浮层 | `TYPE_APPLICATION_OVERLAY`，**全屏吃触摸** | 全屏捕获，吃掉底层触摸 |

### 3.2 z 序（高 → 低）

```
录制浮层  >  取坐标浮层  >  控制球面板  >  脚本列表浮层  >  编辑器浮层(Dialog)  >  诊断/保活/设置 Dialog  >  底层 App
```

> `TYPE_APPLICATION_OVERLAY` 之间按 `addView` 顺序叠放；后加的在上。Dialog Activity 默认在其 task 之上，但 `TYPE_APPLICATION_OVERLAY` 全局窗口会盖在 Dialog 之上——因此「取坐标 / 录制」即使从编辑器 Dialog 内唤起，也会正确盖在编辑器上（沿用 M4 验证过的结论）。

### 3.3 互斥规则表（谁能盖谁、打开一个关什么）

| 打开 | 同时隐藏 / 关闭 | 理由 |
|---|---|---|
| **录制浮层** | 隐藏控制球面板（保留球？→ 关面板，留空）、关闭脚本列表浮层、关闭编辑器浮层 | 录制独占触摸，任何可交互浮层都会抢事件或误导用户 |
| **取坐标浮层** | 隐藏控制球面板（临时） | 取坐标也吃触摸；编辑器 Dialog 保留（picker 盖其上） |
| **编辑器浮层** | 控制球**面板收起为球**（不关球，球保持可见可暂停）；不关列表（列表在编辑器之下或先关） | 编辑时仍可一键暂停；避免叠太多 |
| **脚本列表浮层** | 控制球**面板收起为球**（球作启动器保留）；不强制关其它 | 列表是入口，从球「编辑」唤出 |
| **诊断/保活/设置 Dialog** | 控制球**面板收起为球** | 临时查看，不影响常驻球 |
| **控制球展开面板** | 不关任何浮层 | 面板本身最小，仅自身状态 |

> 通用约定：**凡打开任意「模态浮层/Dialog」时，控制球一律收起为折叠球**（保留球常驻，方便随时暂停），关闭模态浮层后球回到之前折叠位置。全屏吃触摸的「录制 / 取坐标」则彻底隐藏面板。

### 3.4 返回键行为（逐层关闭）

返回键从最上层往下一层关，**永不关闭常驻控制球**：

1. 录制浮层 → 返回 = 取消录制（弹确认，丢弃已录步骤）。
2. 取坐标浮层 → 返回 = 取消取坐标（不回传）。
3. 编辑器浮层 → 返回 = 若有未保存修改弹「放弃修改」确认（沿用 M4 `dialog_discard_*`），否则直接关。
4. 脚本列表浮层 → 返回 = 关闭列表，回到折叠球。
5. 诊断/保活/设置 Dialog → 返回 = dismiss。
6. 控制球**展开面板** → 返回 = 折叠回球（不销毁球）。
7. 控制球**折叠态** → 返回键不响应（球常驻，需用户主动在 MainActivity 入口停止服务才销毁）。

> 实现：`OverlayController` / `OverlayScriptList` 等 `WindowManager` 浮层本身不吃返回键（无焦点）；返回键由当前前台 Activity/Dialog 处理。录制/取坐标为全屏浮层时，需要在其 `View` 上监听 `KeyEvent.KEYCODE_BACK`（或靠承载 Activity）来拦截。

### 3.5 触摸权独占处理

- 同一时刻**只有一个全屏吃触摸浮层**（录制 **或** 取坐标），二者互斥，绝不同时出现（取坐标只在编辑器内可用，录制期不开放，沿用 M4 §3.4.5）。
- 控制球、`FLAG_NOT_FOCUSABLE`，只接收自身小球区域的触摸，不拦截底层 App 的触摸（小球外的事件正常透传到底层）。
- 脚本列表浮层若用 `WindowManager`，同样设 `FLAG_NOT_FOCUSABLE` + 只在浮层卡片区域可点，外部透明区域不拦截（或外部点一下 = 关闭列表）。
- 进录制/取坐标前，主动 `OverlayController.hidePanel()`（仅藏面板，球可后续恢复）；退出后 `OverlayController.showPanel()` 或保持折叠。

## 5. 状态与降级

### 5.1 紧凑球状态色（运行 / 暂停 / 就绪 / 出错 / 后端失效）

| 状态 | 球背景 tint | 球中心图标 | 面板 `btn_overlay_toggle` | 面板 `btn_overlay_toggle` 可点 |
|---|---|---|---|---|
| 运行 | `status_running` 绿 | `ic_pause` | 显示暂停图标 | 可点（→ 暂停） |
| 暂停 | `status_paused` 橙 | `ic_play` | 显示播放图标 | 可点（→ 继续） |
| 就绪 IDLE | `status_stopped` 灰 | `ic_play` | 显示播放图标 | 可点（→ 播放当前脚本） |
| 出错 ERROR | `status_error` 红 | `ic_play` | 显示播放图标 | 可点（→ 重试/播放） |
| 后端失效 DEAD | `status_error` 红 | `ic_play` | 显示播放图标 | **禁用**（`isEnabled=false`，alpha 0.4） |

> 出错与后端失效都显红，区别在：出错是播放逻辑错（后端还在，可重试），DEAD 是无障碍服务被杀（后端没了，禁用开始，提示去诊断）。沿用 M2 §3.4 的 `Health` 判定。

### 5.2 最小信息显示规则（屏幕窄时收敛）

面板信息行 `text_overlay_name` + `text_overlay_loop`：

- **常规**：`text_overlay_name` 显示当前脚本名（`singleLine` + `ellipsize=end`，最长约 8–10 字后截断）；`text_overlay_loop` 显示 `∞·N`（无限已跑 N 巡）或 `N/M`（有限第 N/共 M 次），格式复用 M2 `overlay_loop_format` / `overlay_loop_infinite`。
- **未选脚本**：`text_overlay_name` = `overlay_no_script_selected`（「未选择脚本」），`text_overlay_loop` 隐藏。
- **极窄屏（逻辑宽 < 360dp，如 720×1280 的小窗口模式 / 某些分屏）**：若 `text_overlay_name` 与三按钮同行拥挤，规则为 **隐藏脚本名文字、只留 `text_overlay_loop` 药丸**（图标按钮始终保留，因为三个操作是核心，不可省略）。fixer 在 `refresh()` 里按 `resources.configuration.screenWidthDp < 360` 决定 `text_overlay_name.visibility`；球色已表达状态，少一行文字不影响可用性。
- **状态反馈不依赖文字**：无论是否显示文字，球色 + 中心图标已表达 运行/暂停/就绪/出错，符合「最小信息」要求。

### 5.3 无障碍服务被杀时球的状态

- 触发：`InputBackend.health()` 回报 `Health.DEAD`（无障碍服务被系统回收 / 用户关闭）。
- 表现：折叠球变红、中心图标显示 `ic_play`、`btn_overlay_toggle` 置灰禁用、`btn_overlay_stop` 可点（停止无意义但保留以防卡死）。
- 引导：此时点 `btn_overlay_edit` 仍可进列表 → 列表头「更多」→「诊断」引导重新开启无障碍服务；或在 `MainActivity` 入口提示。DEAD 态不弹「打开列表跳诊断」的旧逻辑（旧 `openList()` 已废弃），改走浮层列表的「更多 → 诊断」入口。
- 恢复：无障碍服务重新开启、`Health` 回到 ALIVE 后，球自动恢复灰/绿，按钮解禁（沿用 `playbackListener` 刷新）。
