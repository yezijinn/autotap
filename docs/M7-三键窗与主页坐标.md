# 精灵点击器 M7 设计规格：三键迷你悬浮窗 + 主页坐标可视化与编辑

> 包名 `com.auto.fairy`，技术栈 **Views + ViewBinding + AppCompat**，无 Compose、无 Material、无新依赖（沿用既有 `recyclerview`）。
> 本文件**覆盖 M6**：坐标可视化与编辑从「全屏浮层」迁移到「App 启动的主页」，运行脚本的迷你悬浮窗精简为三元素。
> 面向 `@fixer`：含完整 XML、View/控制器改造要点、接口建议、性能预算、互斥表与分文件落地清单。
> 中文注释；坐标一律归一化存储（拖动只改归一化值）；720×1280 与 1080×1920 通用（按实际屏像素绘制，不区分分辨率）；**性能优先（少 invalidate、少对象分配、少窗口）**。

---

## 0. 用户新需求（最高优先级，逐条落地）

1. **运行脚本的迷你悬浮窗只显示三个元素**：开始/暂停（未运行显示开始，运行中显示暂停）+ 脚本名（只取前 6 字，更长不显示）+ 停止（完全停止当前运行脚本）。不要浪费空间，尽可能紧凑。
2. **坐标可视化放在 App 启动的主页**（不再默认全屏浮层）：真正的坐标用**十字准心**表示；数字不要圆形包裹，用**纯数字加一点描边**。
3. **点击可视化**：触发点击时，被点击坐标有简易动画效果（如水波/闪烁），让用户看见这个位置被点击了。
4. **坐标编辑常态化放到 App 启动的主页**（主页就是坐标编辑的主界面）。
5. **全局强制**：运行内存尽可能低、资源占用尽量低、性能要求尽量低。

> 与 M6 的冲突处理：M6 的「全屏坐标标记层 + 可移动开关 + 坐标按钮」按本需求第 2/4 条**迁移到主页**，全屏浮层默认关闭（见 §4）。M6 的 4 键面板按第 1 条**精简为三键**（见 §1）。

## 1. 三键迷你悬浮窗（核心改造）

### 1.1 形态决策

| 决策点 | 推荐 | 理由 |
|---|---|---|
| 是否保留 48dp 折叠球 | **保留为折叠态**，点按展开三键条 | 球是唯一的拖动手柄与吸附载体，去掉后无法贴边/移动；折叠态仍是单球，展开态才是三键条 |
| 展开态元素 | **三元素**：开始/暂停切换键 + 脚本名（前 6 字）+ 停止键 | 严格满足需求第 1 条，移除 M6 的「编辑」「坐标」键 |
| 编辑/坐标入口迁移 | 编辑 → 主页脚本列表点开（M6 已支持 `ScriptEditorActivity`）；坐标可视化/编辑 → 主页画布 | 全在 App 内闭环，悬浮窗只负责播放控制 |
| 零间距 | 按钮-文字-按钮一行排布，零间距，2dp 内边距 | 不浪费空间 |

> **折叠球保留但点击展开的就是三键条**：满足「只显示三个按钮」与「可拖动/贴边吸附」两者。折叠态单球不占用运行时的视觉空间；用户点开后只见三键。

### 1.2 尺寸候选（三元素：按钮-文字-按钮）

按钮靶面取 **32dp**（比 M6 的 36dp 更紧凑，仍 >30dp 舒适下限，单手可点）；圆角 6–8dp；内边距 2dp；字号 11–12sp。

| 候选 | 总宽 | 按钮 | 名字区 | 说明 | 结论 |
|---|---|---|---|---|---|
| A | **108dp** | 32dp | 余 ~36dp（weight=1 弹性） | 三元素紧贴 + 2dp 边距的最小合身宽；名字区约 3–4 字可见，其余靠 `take(6)` 截断 | **推荐**：最紧凑且不浪费，常态脚本名多 ≤4 字 |
| B | 96dp | 30dp | 余 ~28dp | 更挤，名字区仅 2–3 字；按钮 30dp 偏紧 | 可选（极致紧凑，小屏友好） |
| C | 120dp | 34dp | 余 ~44dp | 名字区可显 4–5 字；整体略宽 | 可选（名字偏长脚本更友好） |

> **推荐 A（108dp）**：满足「尽可能紧凑」，且 11sp 下多数脚本名（≤4 字）完整显示；超长名按需求第 1 条 `take(6)` 截断（见 §1.3）。若实测 6 字名频繁出现，改 C。
> 高度取 **34dp**（按钮 32dp + 上下各 1dp 内边距；文字单行 11sp 居中）。

### 1.3 文字规则

- 脚本名：`name.take(6)`。**超长不显示省略号**，直接截断前 6 字（用户明确「更长不显示」）。
  - 实现：`textView.text = (name ?: 占位).take(6)`；同时 `singleLine=true` + `ellipsize=end` 作为兜底（极端窄屏下 6 字也放不下时再省略，常态不触发）。
- 无脚本占位：`@string/mini_no_script`（如「无脚本」）。
- 字号 **11sp**；运行状态不影响文字（只改切换键图标）。

### 1.4 状态表达

- 切换键图标：未运行 = `ic_play`；运行中 = `ic_pause`（与 M6 球心逻辑一致）。
- 停止键：常显 `ic_stop`，红色 `status_error` 着色，运行中可点；非运行态仍可点（幂等 `PlaybackController.stop()`）。
- 球色（折叠态）：沿用 M6 `status_running/paused/stopped/error`；DEAD 时切换键置灰禁用。

### 1.6 `OverlayController` 改造要点

- **布局绑定**：`OverlayBallPanelBinding` → `OverlayMiniBarBinding`（由 `overlay_mini_bar.xml` 生成）。
- **移除**：`btn_overlay_edit`、`btn_overlay_coord`、`text_overlay_loop`、`overlay_handle` 的绑定与点击；`CoordinateMarkersController` 的面板入口移除。
- **保留**：`overlay_collapsed` 拖动/吸附（`dragListener`）、`toggleExpanded()`、折叠态球色与 `currentWidth()`。
- **宽度**：`currentWidth()` 展开态取 `@dimen/mini_bar_w`（108dp），折叠态取 `@dimen/overlay_ball_size`（48dp）。
- **`onToggleClicked()`**：逻辑不变（运行中暂停 / 已暂停继续 / 空闲启动当前脚本）。
- **`btnOverlayStop`**：`PlaybackController.stop()`（完全停止）。
- **`refresh()` 简化**：
  - 切换键图标：`running` → `ic_pause` + desc `menu_pause`；否则 `ic_play` + `menu_play`。
  - 球色：沿用 M6 `refresh()` 状态色映射。
  - 脚本名：`currentScriptName(ctx)?.take(6)` 或 `@string/mini_no_script`。
  - **移除** `btn_overlay_coord` 高亮、`text_overlay_loop` 刷新。
- **`hide()` / 编辑器互斥**：不再联动 `CoordinateMarkersController`（全屏层默认关，见 §4）；`hide()` 里去掉 `CoordinateMarkersController.hide` 与 `onStateChanged` 回调（或保留为空操作）。
- **DEAD 态**：切换键置灰禁用（`isEnabled=false; alpha=0.4f`），停止键保留。

## 2. 主页坐标可视化（核心迁移）

### 2.1 主页信息架构

`MainActivity` 维持单 Activity + Fragment 容器；`ScriptListFragment` 重排为**上画布 + 下列表**：

```
┌─────────────────────────────┐
│ AppBar（标题 + 入口，沿用）   │
├─────────────────────────────┤
│ 坐标画布 ScriptCanvas        │  ← 全屏宽，高占 50–60%（@dimen/home_canvas_h 或 weight）
│ 十字准心 + 纯数字 + 点击动画  │
│ [编辑开关浮动按钮 ic_move]    │  ← 可移动切换，常态只读 + 动画
├─────────────────────────────┤
│ 脚本列表（紧凑单行卡片）      │  ← RecyclerView，下方滚动
│  · 每日签到    ∞ · 4步  ⋮    │
│  · 自动领券    3 · 6步  ⋮    │
└─────────────────────────────┘
```

- 画布高度：推荐 **`weight=1`（上）: 列表 `weight=1`（下）** 或画布固定 `@dimen/home_canvas_h`（约屏高 50%）。小屏用 `weight` 更稳。
- 列表：`item_script_card` 复用，已紧凑；建议卡片高度再压 8–12dp（`editor_step_row_height` 思路），标题 14–16sp。

### 2.2 自定义 View：`ScriptCanvas`（复用 CoordinateMarkers 绘制逻辑）

> 新建 `editor/ScriptCanvas.kt`（或 `overlay/`，放主页画布区）。**绘制逻辑复用 `MarkerFlatten.of(steps)`**（序号口径与 M6/编辑器一致：顶层 1..N，循环体父子，Delay 占序号不画点）。
>
> 与 M6 `CoordinateMarkers` 的差异：
> - 坐标表示：**十字准心**（中心点 + 十字线，红，线宽 2dp，臂长 8–10dp），不再是红圆点。
> - 数字：**纯数字 + 描边**（无圆底、无药丸）：先 `Paint.Style.STROKE` 画白描边，再 `Paint.Style.FILL` 画红字。
> - 触摸：常态只读（只播放动画）；开启「编辑开关」后才可拖动改坐标（复用 M6 的 `findAt` / `replaceAt` / `ScriptRepository.save`）。

```kotlin
package com.auto.fairy.editor

import android.content.Context
import android.graphics.Canvas
import android.graphics.Paint
import android.graphics.Rect
import android.util.AttributeSet
import android.view.MotionEvent
import android.view.View
import androidx.core.content.ContextCompat
import com.auto.fairy.R
import com.auto.fairy.ScriptRepository
import com.auto.fairy.core.model.Point
import com.auto.fairy.core.model.Script
import com.auto.fairy.overlay.FlatMark
import com.auto.fairy.overlay.MarkerFlatten
import java.util.Locale

/**
 * 主页坐标画布：十字准心表示坐标 + 纯数字描边 + 点击水波动画 + 常态只读/可拖动编辑。
 * 绘制复用 MarkerFlatten.of 的摊平口径（序号与编辑器卡片一致）。
 */
class ScriptCanvas @JvmOverloads constructor(
    context: Context,
    attrs: AttributeSet? = null,
    defStyleAttr: Int = 0,
) : View(context, attrs, defStyleAttr) {

    data class MarkerEntry(
        var point: Point,
        val label: String,
        val path: com.auto.fairy.overlay.MarkerPath,
        var dragging: Boolean = false,
    )

    // 静态标记（脚本坐标）
    private val entries = ArrayList<MarkerEntry>()
    // 点击动画集合（播放时注入的瞬时高亮，自动清理）
    private val pulses = ArrayList<Pulse>()

    private var script: Script? = null
    private var repository: ScriptRepository? = null
    private var moveEnabled = false
    private val padPx = 2f * resources.displayMetrics.density

    private val density = resources.displayMetrics.density
    private val armPx = resources.getDimension(R.dimen.cross_arm)       // 十字臂长 8–10dp
    private val linePx = 2f * density                                    // 线宽 2dp
    private val numPx = resources.getDimension(R.dimen.cross_label)      // 数字字号 11sp
    private val hitPx = resources.getDimension(R.dimen.marker_hit)       // 拖动命中 20dp
    private val red = ContextCompat.getColor(context, R.color.status_error)

    private val crossPaint = Paint(Paint.ANTI_ALIAS_FLAG).apply {
        style = Paint.Style.STROKE; strokeWidth = linePx; color = red
    }
    private val numFill = Paint(Paint.ANTI_ALIAS_FLAG).apply {
        style = Paint.Style.FILL; color = red; textAlign = Paint.Align.CENTER; textSize = numPx; isFakeBoldText = true
    }
    private val numStroke = Paint(Paint.ANTI_ALIAS_FLAG).apply {
        style = Paint.Style.STROKE; strokeWidth = 3f * density; color = 0xFFFFFFFF.toInt(); textAlign = Paint.Align.CENTER; textSize = numPx; isFakeBoldText = true
    }
    private val ringPaint = Paint(Paint.ANTI_ALIAS_FLAG).apply {
        style = Paint.Style.STROKE; strokeWidth = 2f * density; color = red
    }

    /** 绑定脚本并重建标记。screenW/H 用实际屏像素。 */
    fun bind(script: Script?, screenW: Int, screenH: Int, repo: ScriptRepository) {
        this.script = script
        this.screenW = screenW.coerceAtLeast(1)
        this.screenH = screenH.coerceAtLeast(1)
        this.repository = repo
        entries.clear()
        script?.let { s ->
            MarkerFlatten.of(s.steps).forEach { fm: FlatMark ->
                entries.add(MarkerEntry(fm.point, fm.label, fm.path))
            }
        }
        invalidate()
    }

    fun setMoveEnabled(on: Boolean) { moveEnabled = on; invalidate() }

    /** 播放注入点击：在被点坐标闪现水波（200–300ms，局部刷新，结束自动清理）。 */
    fun pulseAt(nx: Float, ny: Float) {
        if (nx < 0 || ny < 0 || nx > 1 || ny > 1) return
        val p = Pulse(nx, ny, System.currentTimeMillis())
        pulses.add(p)
        // 局部刷新：只 invalid 该点附近矩形，避免整屏重绘
        val px = nx * width; val py = ny * height
        val r = (hitPx * 2).toInt()
        invalidate(Rect((px - r).toInt(), (py - r).toInt(), (px + r).toInt(), (py + r).toInt()))
        // 用 Handler 在动画窗口结束后整体清理一次（低开销，非每帧）
        handler.postDelayed({ pulses.remove(p); invalidate() }, PULSE_MS + 30L)
    }

    private var screenW = 1; private var screenH = 1

    override fun onTouchEvent(e: MotionEvent): Boolean {
        if (!moveEnabled) return false
        // 复用 M6 的命中/拖动逻辑（findAt + replaceAt + repository.save）
        when (e.actionMasked) {
            MotionEvent.ACTION_DOWN -> { /* findAt; dragging=true; invalidate */ return true }
            MotionEvent.ACTION_MOVE -> { /* 更新归一化; invalidate 局部 */ return true }
            MotionEvent.ACTION_UP -> { /* commit: script.replaceAt(path, np) → repo.save → 刷新列表/编辑器 */ return true }
        }
        return false
    }

    override fun onDraw(c: Canvas) {
        super.onDraw(c)
        if (width <= 0 || height <= 0) return
        val drawW = width - padPx * 2; val drawH = height - padPx * 2
        for (m in entries) {
            val cx = padPx + m.point.x * drawW
            val cy = padPx + m.point.y * drawH
            drawCross(c, cx, cy, m.label)
        }
        // 点击动画：扩散圆环 + 中心点放大（纯 invalidate，无属性动画对象）
        val now = System.currentTimeMillis()
        val it = pulses.iterator()
        while (it.hasNext()) {
            val p = it.next()
            val t = (now - p.start).toFloat() / PULSE_MS
            if (t >= 1f) { it.remove(); continue }
            val cx = padPx + p.nx * drawW
            val cy = padPx + p.ny * drawH
            val radius = armPx + t * armPx * 2.5f
            ringPaint.alpha = ((1f - t) * 255).toInt()
            c.drawCircle(cx, cy, radius, ringPaint)
            val dot = armPx * 0.5f * (1f + t)
            c.drawCircle(cx, cy, dot, numFill)
        }
        if (pulses.isNotEmpty()) {
            // 仅当还有动画时续帧；用 postInvalidate 局部驱动，无对象分配
            val p = pulses.first()
            val px = padPx + p.nx * drawW; val py = padPx + p.ny * drawH
            val r = (hitPx * 3).toInt()
            invalidate(Rect((px - r).toInt(), (py - r).toInt(), (px + r).toInt(), (py + r).toInt()))
        }
    }

    private fun drawCross(c: Canvas, cx: Float, cy: Float, label: String) {
        // 十字准心：中心点 + 四条臂
        c.drawLine(cx - armPx, cy, cx - armPx * 0.3f, cy, crossPaint)
        c.drawLine(cx + armPx * 0.3f, cy, cx + armPx, cy, crossPaint)
        c.drawLine(cx, cy - armPx, cx, cy - armPx * 0.3f, crossPaint)
        c.drawLine(cx, cy + armPx * 0.3f, cx, cy + armPx, crossPaint)
        if (label.isEmpty()) return
        // 纯数字 + 描边（先描边后填充）：无圆底、无药丸
        val bx = cx + armPx + 3f * density
        val by = cy
        c.drawText(label, bx, by - (numStroke.ascent() + numStroke.descent()) / 2f, numStroke)
        c.drawText(label, bx, by - (numFill.ascent() + numFill.descent()) / 2f, numFill)
    }

    private data class Pulse(val nx: Float, val ny: Float, val start: Long)

    companion object {
        private const val PULSE_MS = 260L   // 水波时长 200–300ms
    }
}
```

### 2.3 点击动画数据源（接口建议）

播放时每次注入点击，主页画布要闪现动画。当前 `PlaybackController` 只有 `setCursorObserver((TimelineCursor)->Unit)`，没有「本次点击坐标」回调。推荐新增：

```kotlin
// PlaybackController.kt 新增：
interface Listener {
    // ... 既有方法 ...
    /** 一次点击注入完成：回传被点击的归一化坐标（仅点击类动作有值）。 */
    fun onInjected(point: Point) {}
}

// 新增独立观察者（播放高频，避免每个 Listener 都收）：
private var injectObserver: ((Point) -> Unit)? = null
fun setInjectObserver(observer: ((Point) -> Unit)?) { injectObserver = observer }

// 引擎真正派发 Tap 时调用（在 PlaybackEngine 执行 Slice 的 Tap 分支里回调）：
//   injectObserver?.invoke(tapPoint)   // tapPoint 为归一化 Point
```

> **fixer 落地提示**：`Point` 已是归一化（`Point.x/y ∈ [0,1]`），画布直接 `pulseAt(point.x, point.y)` 即可，无需再换算像素（画布内部按 `width/height` 换算）。`PlaybackController` 需把引擎侧 Tap 派发点透传——在 `PlaybackEngine.execute` 的 Tap 分支后补一次回调即可，开销极低（仅一次 lambda 调用）。

若接入引擎改动成本高，备选：用 `cursorObserver` 的游标近似定位（按步序号在画布里找对应 marker 闪现），精度略低但无需改引擎。本版**推荐前者**（精确坐标）。

### 2.4 性能约束（画布）

- 动画只 `invalidate(Rect)` **局部刷新**，不整屏重绘；不在 `onDraw` 里创建对象（Paint 全为字段）。
- 不用 `ValueAnimator`/`ObjectAnimator`（会创建大量帧对象）；用 `postDelayed` + `System.currentTimeMillis()` 差值算进度，续帧只局部 `invalidate`（见 2.2 `onDraw` 末尾）。
- 列表用 `DiffUtil`（或既有 `adapter.submit` 最小刷新），播放进度变化时**不**重建画布标记，只刷新动画。
- 画布 `onPause`（Fragment 不可见）时停止动画与刷新（§5）。

## 3. 主页坐标编辑（常态化）

### 3.1 开关

- 画布右下一个**可移动的浮动切换按钮** `ic_move`（`@+id/btn_canvas_move`），点按在「只读 / 可拖动」间切换。
  - 高亮（红色）= 可拖动；常态（灰）= 只读 + 仅动画。
- 默认**只读**：避免误触；用户主动开启后才能拖动改坐标。
- 复用 M6 `CoordinateMarkers` 的拖动逻辑：`findAt`（20dp 命中）→ 跟手 → 松手 `script.replaceAt(path, np)` → `repository.save()` → 刷新列表/编辑器。

### 3.2 与取坐标工具关系

- 取坐标（`CoordinatePicker`，M4 流程）仍归**编辑器内**：精确像素取点，全屏吃触摸。
- 主页拖动是**常态快捷编辑**（粗略改某点位置）；二者目的不冲突，但都吃触摸 → **互斥**（同 M6 §3.4）：从编辑器唤起 `CoordinatePicker` 前，若主页可拖动开着，临时关可移动（画布仍显示但变只读），退出 picker 恢复。
- 编辑保存后画布即时 `bind()` 刷新；与列表/浮层/标记层数据一致（均走 `ScriptRepository` 监听器）。

### 3.3 写回脚本（复用 M6 纯函数）

直接复用 `overlay/MarkerPath.kt` 的 `MarkerPath` 密封类与 `Script.replaceAt(path, np)`（M6 已实现，本版不重造）。主页画布拖动松手调用同一套即可。

## 4. 全屏标记层的去留（M6 改造）

### 4.1 决策

| 方案 | 推荐 | 理由 |
|---|---|---|
| **保留 `CoordinateMarkersController` 但默认关闭**，仅主页一个开关可打开 | **推荐** | 代码已就绪、零常驻开销（未打开时不创建任何窗口）；需要时用户主动开全屏叠加看坐标，与主页画布互不干扰 |
| 完全移除入口 | 备选（更省） | 少一个类/布局，但失去「全屏看坐标」能力；若需求确认永不看全屏，可删 |

> **内存/性能结论**：`CoordinateMarkersController` **默认不创建窗口**（M6 已 `added=false` 初始态），因此「少一个常驻全屏窗口」的目标已达成——它只在用户从主页打开时才实例化。本版只做两件事：
> 1. 移除 `OverlayController` 面板上的 `btn_overlay_coord` 入口（§1.6）。
> 2. 主页新增一个开关按钮 `btn_fullscreen_markers`（默认关）调用 `CoordinateMarkersController.toggle(ctx)`，并同步高亮。

### 4.2 主页如何打开/关闭

- `ScriptListFragment` 顶部加一个 `ic_coord` 小按钮（与 `btn_canvas_move` 并列或同处），`setOnClickListener { CoordinateMarkersController.toggle(requireContext()) }`。
- 高亮态随 `CoordinateMarkersController.isShowing()` 刷新。
- 互斥沿用 M6 §4：`CoordinateMarkersController.setSuppressed(ctx, "editor", true)` 在编辑器/录制/取坐标打开时隐藏全屏层。

## 5. 性能与内存（全局强制要求）

### 5.1 本版所有低开销措施

| 措施 | 说明 |
|---|---|
| **单窗口（去全屏层常驻）** | `CoordinateMarkersController` 默认不建窗口，常驻 overlay 只剩三键迷你条一个 |
| **动画局部刷新** | 画布 `invalidate(Rect)` 只刷点击点附近；无全屏重绘 |
| **无属性动画对象** | 点击动画用 `postDelayed` + 时间差值，续帧只局部 invalidate；不创建 `ValueAnimator`/`ObjectAnimator` |
| **列表复用** | `RecyclerView` + 既有 `adapter.submit` 最小刷新；播放进度变化不重建画布标记 |
| **无新依赖** | 全用既有 `recyclerview` / `View` / `Paint`，不引 Compose/Material |
| **画布 only when visible** | `ScriptListFragment.onPause()` 停止动画与刷新（`handler.removeCallbacks` / 清 `pulses`）；`onResume()` 恢复 |
| **Paint 复用** | 所有 `Paint` 为 View 字段，不在 `onDraw` 内 new |
| **归一化存储** | 拖动只改归一化值，绘制按实际屏像素换算，720×1280 / 1080×1920 通用无分支 |

### 5.2 内存预算

| 项目 | 估算常驻开销 | 等级 |
|---|---|---|
| 三键迷你条窗口（一个 `TYPE_APPLICATION_OVERLAY`，108×34dp） | ~几十 KB（View + Binding），无循环/动画 | 可忽略 |
| 主页 `ScriptCanvas` View（仅在 App 前台存在，随 Fragment 销毁） | 标记列表 `ArrayList<MarkerEntry>` 随脚本大小，通常 <1KB；Paint 字段常驻但极小 | 可忽略 |
| `CoordinateMarkersController`（默认关） | 0（未实例化窗口） | 0 |
| 点击动画 `pulses` | 最多数个 `Pulse` 对象，260ms 后清理 | 可忽略 |

> **最低配目标**：4 核 / 2GB RAM / Android 8 的低端机；本版常驻内存增量 < 200KB，主线程每帧绘制开销仅在播放点击动画时存在（<300ms 瞬时），其余常态为静态绘制 + 列表滚动。满足「运行内存尽可能低、资源占用尽量低、性能要求尽量低」。

## 7. 互斥与层级

### 7.1 互斥表

| 打开 | 同时处理 | 理由 |
|---|---|---|
| **迷你条（播放常驻）** | 可拖动（三键条本身不占画布触摸）；主页打开时画布显示点击动画 | 迷你条只占小球/三键区域，不抢焦点；主页画布在自己窗口内动画 |
| **主页画布编辑（可拖动开）** | 与取坐标 `CoordinatePicker` 互斥：唤起 picker 前临时关可移动 | 两者都吃触摸，避免抢事件（同 M6 §3.4） |
| **编辑器浮层** | 隐藏全屏标记层（`setSuppressed("editor", true)`）；主页画布仍可见但只读 | 编辑器有自己的迷你屏，全屏层重复且挡操作 |
| **录制 / 取坐标** | 隐藏全屏标记层；取坐标时若可移动开则临时关 | 全屏吃触摸，任何可交互层都抢事件 |
| **全屏标记层（用户从主页开）** | 主页画布仍显示（两者叠加不冲突，一个全屏一个主页内）；控制球可点 | 标记层只读态 `FLAG_NOT_TOUCHABLE` 透传，不妨碍 |
| **列表浮层（OverlayScriptList）** | 与迷你条共存；全屏标记层按 suppressors 隐藏 | 列表浮层是 90%×70% 窗口，不挡全屏标记层的非交互区 |

### 7.2 层级（高 → 低，更新）

```
录制浮层 > 取坐标浮层 > 全屏坐标标记层(TYPE_APPLICATION_OVERLAY, 默认关) > 控制球迷你条 > 脚本列表浮层 > 编辑器浮层(Dialog) > 主页(App)
```

> 主页画布是 App 自身内容，位于最底层；迷你条作为 overlay 在其上常驻。

## 9. 设计权衡小结（给 fixer 的决策依据）

1. **迷你条 108dp 而非 96/120**：三元素（32+名字+32）最紧凑合身；96 名字区仅 2–3 字、120 偏宽；常态脚本名多 ≤4 字，108 足够，超长按需求 `take(6)` 截断。
2. **保留折叠球**：球是唯一拖动/吸附手柄，折叠态单球不占运行视觉空间，点开展开即三键——同时满足「只显示三个按钮」与「可移动」。
3. **坐标可视化迁主页、全屏层默认关**：满足需求第 2/4 条；全屏层代码保留但零常驻开销，用户需要时从主页开。
4. **十字准心 + 纯数字描边（无圆底）**：需求第 2 条明确要求；比 M6 的红圆点药丸更轻、更省绘制。
5. **点击动画局部刷新、无属性动画**：需求第 3 条「看见被点位置」+ 第 5 条「性能优先」的双重约束；用 `postDelayed` + 时间差值，续帧只 `invalidate(Rect)`。
6. **点击坐标数据源**：推荐引擎 Tap 派发后透传归一化 `Point`（`onInjected`），精确；备选用游标近似（不改引擎但精度低）。
7. **主页拖动 vs 取坐标互斥**：沿用 M6 的临时关可移动策略，避免抢触摸。
8. **Delay 占序号不画点**：保证数字与编辑器卡片一一对应（沿用 M6 口径，主页画布复用 `MarkerFlatten`）。

---

## 10. 风险与待确认

- **引擎回调接入**：`onInjected` 需在 `PlaybackEngine.execute` 的 Tap 分支补调用，涉及引擎文件（非本版主体），fixer 落地时确认 `Point` 归一化口径一致。
- **画布高度适配**：`home_canvas_h=300dp` 为固定值，小屏（如 720×1280 实际 ~640dp 高）可能偏挤；fixer 可改为 `weight` 布局（画布 `weight=1`、列表 `weight=1`）更弹性。
- **`mini_bar_w` 实测**：若 6 字脚本名频繁出现且需完整显示，改 `120dp`（候选 C）；本版默认 108dp（候选 A）。
