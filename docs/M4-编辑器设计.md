# 精灵点击器 M4 设计规格：脚本编辑器 + 取坐标工具 + 坐标可视化

> 包名 `com.auto.fairy`，技术栈 **Views + ViewBinding + AppCompat**，沿用 M2 视觉规范（配色 / 间距 / 圆角 / 字号 / 图标全部沿用），**不引入 Compose、不引入 Material**。
> 本文件面向 `@fixer`：每个布局均为可直接落地的 `res/layout/*.xml` 规格，含 view id 命名规范、drawable / strings 清单与自定义 View 绘制逻辑。
> 坐标一律**归一化存储**（`Point(x,y) ∈ [0,1]`），编辑时按设备真实屏幕尺寸换算像素显示；所有尺寸用 `dimens.xml` 的 `space_*` / `corner_*` / `touch_target`，不硬编码。

## 1. 总体架构决策（为什么是 Activity 而非 Fragment）

**结论：`ScriptEditorActivity`（独立 Activity），宿主于 `MainActivity` 之上，`startActivityForResult` 回传保存结果。**

理由（给 fixer 的取舍说明）：
1. **生命周期隔离**：编辑器是深层编辑界面，独立 Activity 的 `onBackPressed` / 保存拦截（未保存提示）天然干净，不污染 M2 的主页 Fragment 返回栈。
2. **与浮层互斥简单**：M2 的 `OverlayController`（播放悬浮窗）和 `RecordOverlay`（录制浮层）都是 `WindowManager` 全局窗口。编辑器用独立 Activity，进入编辑时 `PlaybackController` 已暂停/停止，`OverlayController` 收到「编辑中」状态直接隐藏面板即可，无需在 Fragment 容器里协调可见性。
3. **取坐标浮层方案统一**：CoordinatePicker 用 `TYPE_APPLICATION_OVERLAY`，它必须叠加在编辑器 Activity 之上且能被编辑 Activity 控制显隐——独立 Activity 持有 picker 的 `WindowManager` 引用最清晰。

> 若团队坚持「单 Activity 多 Fragment」总架构，则把 §2 的 `activity_script_editor.xml` 改为 `fragment_script_editor.xml`，由 `MainActivity` 用 `replace` 切到 `ScriptEditorFragment` 并屏蔽底部 FAB；其余布局与逻辑完全不变。

> **摘要文案规则（fixer 在 `StepAdapter` 里拼，统一调用 `StepSummary.summaryOf(step, screen)`）**：
> - Tap：`点击 (%1$d, %2$d)` + 副行 `归一化 %3$.2f, %4$.2f · %5$dms`
> - Swipe：`滑动 %1$d 点` + 副行 `起点→终点 · %2$dms`（多段轨迹取首末点坐标）
> - Delay：`延时 %1$dms` + 副行 `节奏等待`
> - Loop：`循环 %1$s` + 副行 `内含 %2$d 步`（%1$s 为 `editor_loop_infinite`「∞」或 `N 次`）
> - Multi（M4 暂不支持编辑入口，导入脚本可能含）：`多指 %1$d 轨迹` + 副行 `%2$dms`
>
> 像素值用设备真实屏幕宽高（或 `script.screen`，见 §5.1）由归一化反算：`px = round(norm * size)`。

   - 松手不确认：准星停在最后位置，等用户点「确认」或「取消」。
2. **拖准星 vs 点击**：准星默认跟手；同时顶部读数实时显示。若用户想精细微调，可在准星区域内二次拖动。本 M4 简化为「手指落点即目标点」，长按/拖动均实时跟手。

     - 录制期：取坐标工具**不在录制期开放**（录制本身就在采坐标），因此 picker 只在编辑器 Activity 内可用，`RecordOverlay` 不会同时出现。
   - 浮层 flag：`TYPE_APPLICATION_OVERLAY`，`FLAG_NOT_FOCUSABLE` 不需要（需要接收触摸）；`FLAG_LAYOUT_IN_SCREEN`。Android 12+ 注意 `TYPE_APPLICATION_OVERLAY` 权限已在 M2 处理。
6. **放大镜效果**：**M4 降级为「十字线 + 坐标读数 + 半透明遮罩」，不实现位图放大**（成本高、且 overlay 拿不到底层屏幕位图）。`picker_scrim` 用 `@color/picker_scrim = #66000000`（比录制遮罩浅，保证能看到底层画面轮廓）。准星用 `CoordinateCrosshair` 绘制：中心实心点 + 十字线 + 外圈环（`@dimen/picker_ring_radius`），颜色用主色/白描边保证任何背景下可读。

### 3.5 `CoordinateCrosshair` 自定义 View 绘制逻辑

```kotlin
// 伪代码，fixer 落地。绘制：十字线 + 外环 + 中心圆点，跟随 lastX/lastY。
class CoordinateCrosshair(context, attrs) : View(context, attrs) {
    private var lastX = 0f
    private var lastY = 0f
    private val paintCross = Paint().apply { color = brand; strokeWidth = 2f }
    private val paintRing = Paint().apply { color = white; style = STROKE; strokeWidth = 2f }
    private val paintDot = Paint().apply { color = brand }

    fun setPoint(x: Float, y: Float) { lastX = x; lastY = y; invalidate() }

    override fun onDraw(canvas: Canvas) {
        // 十字线贯穿全屏
        canvas.drawLine(0f, lastY, width.toFloat(), lastY, paintCross)
        canvas.drawLine(lastX, 0f, lastX, height.toFloat(), paintCross)
        // 外环
        canvas.drawCircle(lastX, lastY, RING_RADIUS, paintRing)
        // 中心圆点
        canvas.drawCircle(lastX, lastY, 4f, paintDot)
    }
}
```

## 4. 坐标可视化（CoordinateVisualizer）

**目的**：让用户一眼看到脚本会在哪些位置点击/滑动（用户明确要求「绘制坐标位置」）。两个使用场景：

1. **编辑器内**（§2.1 `viz_miniscreen`）：迷你屏幕矩形，绘制所有步骤的坐标点 + 序号，随编辑实时刷新。
2. **预览全屏**（`overlay_coord_preview.xml`，点编辑器「预览」弹出）：暗化全屏 + 大号屏幕矩形 + 所有点（半透明圆点 + 数字标签）+ 点击数字标签可定位。

### 4.1 `CoordinateVisualizer` 自定义 View（编辑器迷你屏 + 预览共用）

绘制输入：`List<Point>`（归一化）+ 当前屏幕宽高比 + 序号映射。

```kotlin
// 伪代码。fixer 落地。
class CoordinateVisualizer(context, attrs) : View(context, attrs) {
    data class Mark(val point: Point, val label: String, val type: StepType)

    private val marks = mutableListOf<Mark>()
    private var aspectW = 9f   // 屏幕比例，按 script.screen 或设备设
    private var aspectH = 16f

    fun setMarks(list: List<Mark>, w: Int, h: Int) {
        marks.clear(); marks.addAll(list)
        aspectW = w.toFloat(); aspectH = h.toFloat()
        requestLayout(); invalidate()
    }

    // 让 View 高度按屏幕比例自适应宽度（miniscreen 锁定最大宽，预览按父容器）
    override fun onMeasure(wSpec: Int, hSpec: Int) {
        val w = MeasureSpec.getSize(wSpec)
        val h = (w * aspectH / aspectW).toInt().coerceAtLeast(1)
        setMeasuredDimension(w, h)
    }

    override fun onDraw(canvas: Canvas) {
        val pad = 2f
        val drawW = width - pad * 2
        val drawH = height - pad * 2
        // 背景已在 xml 用 bg_viz_screen（深色屏底 + 细边框）
        for (m in marks) {
            val cx = pad + m.point.x * drawW
            val cy = pad + m.point.y * drawH
            // 半透明圆点
            paintPoint.alpha = 160
            canvas.drawCircle(cx, cy, POINT_RADIUS, paintPoint)
            // 白描边
            canvas.drawCircle(cx, cy, POINT_RADIUS, paintStroke)
            // 序号数字
            canvas.drawText(m.label, cx, cy - POINT_RADIUS - 2, paintLabel)
        }
    }
}
```

**要点**：
- 圆点颜色按类型区分（`ic_step_tap` 主色 / `swipe` 橙 / `delay` 灰 / `loop` 绿），半透明 + 白描边保证在深色屏底可读。
- 序号：扁平化展平后的全局步骤序号（Loop 内嵌步骤按展开顺序编号），与 `item_step_card` 的 `text_step_index` 一致，方便对照。
- 两种屏适配：720×1280（比例 9:16）与 1080×1920（同样 9:16，只是像素不同）——归一化坐标与像素无关，比例一致，绘制无需区分；像素读数仅在编辑显示时按真实尺寸反算（§5.1）。

## 5. 播放控制完善 & 坐标反算

### 5.1 像素反算规则（fixer 统一实现 `CoordDisplay`）

```kotlin
// 所有编辑界面显示像素时调用，保证 720×1280 与 1080×1920 一致换算
object CoordDisplay {
    /** 取用于显示的屏幕尺寸：优先 script.screen（录制/导入时的真实尺寸），否则设备真实尺寸。 */
    fun screenFor(script: Script?): Pair<Int, Int> {
        val dev = deviceRealSize()            // DisplayMetrics real metrics
        val s = script?.screen
        return if (s != null && s.w > 0 && s.h > 0) s.w to s.h else dev.first to dev.second
    }
    fun toPx(p: Point, w: Int, h: Int) = Pair(round(p.x * w), round(p.y * h))
}
```

- 归一化存储不变；显示时按上面规则反算像素。
- 列表摘要、对话框坐标块、picker 读数全部走 `CoordDisplay`，一处修改全局一致。
