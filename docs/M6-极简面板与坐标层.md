# 精灵点击器 M6 设计规格：极简面板 + 坐标显示层

> 包名 `com.auto.fairy`，技术栈 **Views + ViewBinding + AppCompat**，沿用 M5 的浮层化体系与深色半透明风格，**不引入 Compose、不引入 Material、不新增依赖**（除既有 `recyclerview`）。
> 本文件面向 `@fixer`：覆盖 M5 的「48dp 球 + 160dp 面板」为更小的面板，并新增「坐标显示层 + 坐标拖动」两个能力。所有布局为可直接落地的 `res/layout/*.xml`，含 view id、drawable / strings / dimens 追加清单与控制器改造要点。
> 中文注释；坐标一律归一化存储（拖动只改归一化值）；720×1280 与 1080×1920 通用（按实际屏幕像素换算绘制，不区分分辨率）。

---

## 0. 用户原话（最高优先级，逐条落地）

1. **「尽一切可能缩小悬浮窗口，只需要保留 开始/暂停/停止/编辑 即可。」**
   → 折叠球保留 48dp（已是紧凑下限之上），展开面板在 M5 的 160dp 基础上继续收窄；核心三键（开始/暂停切换、停止、编辑）保持不变，**额外** 的「坐标」开关以一颗小图标按钮并入面板（见 §1.3 说明：这是用户第 3 条明确要求的新开关，与「只保留四键」不冲突——坐标开关是「显示层」的开关，不是播放操作键）。
2. **「字体 图标 控件 之间不应该留间隔 不要间距 尽可能紧凑 挨近 不要间隔」**
   → 信息行与按钮行**零间距**；按钮之间**零间距**紧贴；面板内边距缩到 2dp；图标 20–22dp；按钮靶面压到 **36dp**（紧凑下限）；字号 11–12sp。所有 `space_s(8)/space_xs(4)` 在面板内一律改用 `space_2xs(2)/space_none(0)`。
3. **「补充一个显示开关：能持久显示一个脚本里的每个点击的坐标，画一个坐标点 并标上数字 是第几步。例如 画一个红色加粗的圆点 (333,444) 同时标上数字1 表示这是第一步的点击坐标。开关开启时，会持久显示在屏幕上。」**
   → 新增全屏「坐标标记层」`CoordinateMarkers`：红色加粗圆点 + 白描边 + 步骤数字标签（第几步）。开关持久化到 `SharedPreferences`，开启后常驻屏幕。
4. **「再多一个选项：是否可以直接移动这些坐标。如果开启了可移动，那么用户可以直接拖动该坐标 直接改变点击位置 而不需要打开编辑去改坐标。」**
   → 标记层再开第二个开关「可移动」：开启后坐标点可拖动，松手即把新归一化坐标写回脚本（`ScriptRepository.save`），并刷新编辑器/列表/标记层。详见 §3。

## 1. 极简悬浮面板（核心改造）

### 1.1 设计原则（相对 M5 收紧）

- 折叠态单球（48dp）不变。
- 展开态面板继续收窄、去间距：
  - 圆角从 `corner_panel(16dp)` 降到 **8dp**（新增 `overlay_panel_radius`）。
  - 内边距 `4dp → 2dp`（`space_xs → space_2xs`）。
  - 信息行（脚本名 + 循环）压成**最薄一条**，与按钮行**零间距**紧贴。
  - 按钮行：开始/暂停切换、停止、编辑、**坐标（新）** 四颗图标按钮，彼此**零间距**、靶面 **36dp**、图标 **22dp**、按钮 `padding=7dp`。
  - 字号：信息行 11sp，无第二行文案。
- 状态表达沿用 M5：球色（运行绿 / 暂停橙 / 就绪灰 / 出错红）+ 球心图标（运行中显示暂停图标）。面板不再有状态文字。

### 1.2 关于「坐标」开关放在哪（与「只保留四键」的协调）

用户第 1 条要求面板「只保留 开始/暂停/停止/编辑」，第 3 条又要求新增「坐标显示开关」。二者调和方式：

- **播放操作键严格保持三颗**（开始/暂停切换、停止、编辑），符合第 1 条。
- 「坐标」开关作为第 4 颗**小图标按钮**并入面板按钮行——它是「显示层」的总开关（点击 = 开/关标记层），不是播放操作，且用户第 3 条明确要求把它做出来，故归入面板合理。
- 若坚持面板只放三键，可改为：**长按折叠球**切换标记层显示（不占面板空间）。但长按球已被 M5 占用于「展开面板」，冲突。因此**推荐方案：面板第 4 颗坐标图标按钮**（零间距并入，几乎不增加宽度，见 §1.3）。

### 1.3 面板宽度候选（4 键 + 信息条）

按钮靶面 36dp × 4 = 144dp；两侧内边距 2dp × 2 = 4dp；合计 **148dp**。信息条为顶部一条，不额外加宽。

| 候选 | 面板宽 | 按钮靶面 | 说明 | 结论 |
|---|---|---|---|---|
| A | **148dp** | 36dp | 4 键紧贴 + 2dp 边距的最小合身宽；信息条在上方一条 | **推荐**：满足「四键 + 信息条」且比 M5 的 160dp 更窄 |
| B | 140dp | 33dp | 按钮压到 33dp，低于舒适下限，小屏误触上升 | 可选（极致紧凑） |
| C | 132dp | 31dp | 按钮仅 31dp，明显偏挤；图标 20dp 才放得下 | 不推荐，仅对比 |

> 原提示里的 108/120/132 三档，是按「三键 + 信息同行」估的；本方案因新增第 4 颗坐标键，三键档位不再适用，故重估为 148/140/132（132 仅能容纳 4×31dp 小键）。**推荐 A（148dp）**：在「合规靶面 ≥ 40 过于宽松、36 为实操下限」之间取平衡，且比 M5 收窄 ~8%。

### 1.4 状态色映射（沿用 M5 §5.1，不重复）

运行绿 `status_running` / 暂停橙 `status_paused` / 就绪灰 `status_stopped` / 出错红 `status_error`；DEAD 时球变红且 `btn_overlay_toggle` 置灰禁用。`refresh()` 逻辑沿用 M5，仅新增「坐标按钮高亮」与「窄屏隐藏脚本名」（沿用 `NARROW_WIDTH_DP=360`）。

## 2. 坐标显示层（新浮层，核心新增）

### 2.1 触发与生命周期

- 入口：面板 `btn_overlay_coord` 点击 → 切换标记层显示（`CoordinateMarkersController.toggle()`）。
- 持久化：`SharedPreferences` 键 `coord_layer_on`（显示开关）、`coord_layer_move`（可移动开关），位于 `overlay_window` 或独立 `coord_layer` 偏好文件。
- 自动刷新：脚本切换（播放脚本变化）、编辑器保存后（`ScriptRepository` 监听器）、播放进度变化（高亮当前步，TODO）时，标记层重新取当前脚本并 `setScript()`。
- 当前脚本取法（与 `OverlayController.currentScriptName` 一致）：`PlaybackController.playingScriptId ?: repo.lastPlayedId`，再 `repo.load(id)`。

### 2.2 绘制内容

- **每个关键点 = 红色加粗圆点 + 白描边 + 步骤数字标签（第几步）**。
  - 圆点直径 `marker_radius*2 = 12dp`，填充红 `#EB5757`（复用 `status_error`），描边白 2dp。
  - 数字标签：10sp 白字，**红底白字药丸**或**红字白描边**（保证任何背景可读；推荐红底白字，最稳）。
- **类型与关键点**：
  - `Tap`：画第 1 个点（关键点）。
  - `Swipe`：画**起点 + 终点**两个圆点，**同一数字**（同一步）；起点正常标号，终点可不标数字或标同号（推荐：两点都标同号，终点用空心或较小点区分）。
  - `Multi`：**每根手指都画**（M5 的 `CoordinateVisualizer` 只画了第一指第一点，本层修复为全画）。
  - `Loop`：循环体递归编号，循环本身不画点（与编辑器卡片序号一致）。
  - `Delay`：不画点，但**占序号**（理由：编辑器里延时是一张独立卡片，序号必须连续对应卡片；不画点只是因为它没有坐标。若跳过编号，圆点数字会与编辑器卡片对不上，用户拖动时找不到对应步骤）。
- **序号口径**：与编辑器卡片一致 = `CoordinateVisualizer.marksOf()` 的 `label`（顶层 1..N，循环体递归「父.子」）。本层复用 `CoordinateVisualizer.marksOf()` 做摊平（顺带修复 Multi 全画、Swipe 终点标号），见 §3 的 `MarkerEntry` 改造。
- **屏幕换算**：标记层为全屏 View，归一化点直接乘当前屏幕像素：`px = point.x * screenW`，`py = point.y * screenH`（720×1280 / 1080×1920 自动按实际尺寸，无差异）。

## 3. 坐标拖动（重点新增）

### 3.1 开关与交互

- 第二个开关「可移动」（`btn_markers_move` / `coord_layer_move`）：开启后坐标点可拖动。
- 命中：手指按下时做命中测试，`distance(press, markerPx) <= marker_hit(20dp)` 即命中该点。
- 视觉反馈：拖动中该圆点放大 **1.5×**（半径 ×1.5）、数字加粗、并显示**实时像素坐标小气泡**（如 `(333,444)`）。
- 拖动：`onTouch` 命中后 `return true` 吃掉该手势（不影响底层 App 的其它区域，见 §3.3）；实时把手指位置换算成归一化坐标 `nx = rawX/screenW, ny = rawY/screenH`，夹紧 `[0,1]`。
- 松手：用新归一化坐标替换该点的原坐标，重建脚本并 `ScriptRepository.save()`，随后刷新编辑器/列表/标记层。

### 3.2 写回脚本（关键：保留路径以便重建不可变 Step 树）

`Step` 是不可变 data class，拖动不能直接改字段，必须重建整棵步骤树。方案：摊平时为每个标记记录一条**路径 `MarkerPath`**，松手时调用 `Script.replaceAt(path, newPoint)` 返回新 `Script`。

```kotlin
// 标记路径：定位「脚本里哪一个点的第几个坐标」
sealed class MarkerPath {
    data class Tap(val index: Int) : MarkerPath()          // 顶层第 index 步（Tap）的第 0 点
    data class Swipe(val index: Int, val point: Int) : MarkerPath() // 第 index 步 Swipe 的第 point 个点
    data class Multi(val index: Int, val finger: Int) : MarkerPath() // 第 index 步 Multi 的第 finger 指第 0 点
    data class Loop(val index: Int, val inner: MarkerPath) : MarkerPath() // 第 index 步 Loop，体内再定位
}

// 重建：返回替换了目标点的新脚本（纯函数，不修改原对象）
fun Script.replaceAt(path: MarkerPath, np: Point): Script =
    copy(steps = steps.replaceAt(path))

private fun List<Step>.replaceAt(path: MarkerPath): List<Step> =
    mapIndexed { i, step ->
        when (path) {
            is MarkerPath.Tap -> if (i == path.index) {
                (step as Step.Tap).copy(points = listOf(np)) // Tap 单点
            } else step
            is MarkerPath.Swipe -> if (i == path.index) {
                val s = step as Step.Swipe
                // 替换第 point 个点（起点 point=0，终点 point=last）
                val pts = s.points.mapIndexed { k, p -> if (k == path.point) np else p }
                s.copy(points = pts)
            } else step
            is MarkerPath.Multi -> if (i == path.index) {
                val m = step as Step.Multi
                // 替换第 finger 指的第 0 点（Multi 每指单点为主）
                val pts = m.points.mapIndexed { f, fingerPts ->
                    if (f == path.finger) fingerPts.mapIndexed { k, p -> if (k == 0) np else p } else fingerPts
                }
                m.copy(points = pts)
            } else step
            is MarkerPath.Loop -> if (i == path.index) {
                val l = step as Step.Loop
                l.copy(body = l.body.replaceAt(path.inner))
            } else step
        }
    }
```

> 摊平（复用并增强 `CoordinateVisualizer.marksOf`）：遍历步骤树，遇到 `Loop` 包裹 `MarkerPath.Loop(index, inner)` 继续递归；`Tap` 生成 `MarkerPath.Tap`；`Swipe` 生成起点 `Swipe(index,0)` 与终点 `Swipe(index,last)`（同号）；`Multi` 每指生成 `Multi(index,finger)`。**延时不生成标记但占位序号**（与编辑器卡片对齐）。

### 3.3 触摸权与透传（避免遮挡底层 App）

- 标记层窗口：`TYPE_APPLICATION_OVERLAY` + `FLAG_NOT_FOCUSABLE` + `FLAG_LAYOUT_IN_SCREEN`，全屏透明。
- 根 `FrameLayout` 背景透明、`setOnTouchListener` 默认 `return false`（非命中区域手势透传到底层 App）。
- `CoordinateMarkers` 的 `onTouchEvent`：**命中圆点且「可移动」开启**时处理拖动并 `return true`；否则 `return false`。这样只有拖动坐标时拦截手势，平时底层 App 完全可操作。
- 控制球窗口在标记层之下仍可点：顶层标记层对非命中区域 `return false`，事件会下发给下层窗口（同类型 overlay 跨窗口透传按此模式工作）。

### 3.4 与取坐标浮层互斥（二选一，推荐方案）

「可移动」与「取坐标 `CoordinatePicker`」都能改坐标、且都会吃触摸，必须互斥。

- **推荐：开「可移动」时禁用取坐标**。理由：`CoordinatePicker` 是编辑器内的一次性精确取点（全屏吃触摸、精确像素），「可移动」是屏幕上的粗略拖拽；两者目的重叠，同时开着会让用户困惑且抢触摸。具体：从编辑器唤起 `CoordinatePicker` 前，若 `coord_layer_move` 为开，先临时关掉可移动（标记层仍显示但变只读），退出 picker 后恢复原状态。反之，若用户正在可移动拖拽中，编辑器取坐标入口本就不可用（编辑器打开时全局标记层隐藏，见 §4）。
- 备选（不推荐）：取坐标时关掉整个标记层。缺点是退出 picker 后要用户重新开显示，体验断。

### 3.5 边界与多指策略

- 坐标夹紧 `[0,1]`：`nx = rawX/screenW).coerceIn(0f,1f)`，`ny` 同理。
- 多指同组：推荐**只动单指**（一次拖动只移动一个被命中的点）。理由：Swipe 起终点、Multi 多指同时平移会让「拖动 = 精确改某点」的直觉失效，且容易误移相邻点；单指 + 用户逐个拖更可控。若后续需要整体平移一组，再加「框选/群组拖动」开关，本版不做。

### 3.6 `CoordinateMarkers` View 骨架（fixer 落地参考）

```kotlin
package com.auto.fairy.overlay

class CoordinateMarkers @JvmOverloads constructor(
    ctx: Context, attrs: AttributeSet? = null, def: Int = 0,
) : View(ctx, attrs, def) {

    /** 一个可绘制/可拖动的标记：坐标(归一化) + 序号 + 路径(写回用) + 是否高亮。 */
    data class MarkerEntry(
        val point: Point, val label: String, val path: MarkerPath,
        var dragging: Boolean = false,
    )

    private val entries = ArrayList<MarkerEntry>()
    private var screenW = 1; private var screenH = 1
    private var moveEnabled = false
    private var onCommit: ((Script) -> Unit)? = null   // 松手写回回调
    private var repo: ScriptRepository? = null
    private var currentScript: Script? = null

    fun setScript(script: Script?, w: Int, h: Int, move: Boolean, repo: ScriptRepository, commit: (Script)->Unit) {
        screenW = w; screenH = h; moveEnabled = move; this.repo = repo
        currentScript = script; onCommit = commit
        entries.clear()
        if (script != null) buildEntries(script.steps, null)  // 复用 marksOf 思路 + 记录 path
        invalidate()
    }

    // 命中测试：返回距按下点最近且在 marker_hit 内的标记
    private fun hit(rx: Float, ry: Float): MarkerEntry? { /* 换算 px 后比较距离 */ }

    override fun onTouchEvent(e: MotionEvent): Boolean {
        if (!moveEnabled) return false
        when (e.actionMasked) {
            MotionEvent.ACTION_DOWN -> hit(e.rawX, e.rawY)?.let { drag = it; it.dragging = true; return true }
            MotionEvent.ACTION_MOVE -> drag?.let { /* 实时更新归一化 + 气泡 + invalidate */ ; return true }
            MotionEvent.ACTION_UP -> drag?.let {
                it.dragging = false
                val np = Point((e.rawX/screenW).coerceIn(0f,1f), (e.rawY/screenH).coerceIn(0f,1f))
                currentScript?.replaceAt(it.path, np)?.let { ns ->
                    repo?.save(ns); onCommit?.invoke(ns)   // 刷新编辑器/列表/标记层
                }
                drag = null; return true
            }
        }
        return false
    }

    override fun onDraw(c: Canvas) {
        // 每个 entry：红底白字药丸数字 + 红圆点(放大1.5x if dragging) + 白描边
        // px = point.x*screenW, py = point.y*screenH
    }
}
```

## 4. 互斥与层级

### 4.1 同时存在的浮层（更新 M5 §3.1）

| 浮层 | 类型 | 触摸行为 |
|---|---|---|
| 录制浮层 | `TYPE_APPLICATION_OVERLAY`，全屏吃触摸 | 独占，盖一切 |
| 取坐标浮层 | `TYPE_APPLICATION_OVERLAY`，全屏吃触摸 | 独占（与可移动互斥，§3.4） |
| **坐标标记层** | `TYPE_APPLICATION_OVERLAY`，全屏透明 | **仅命中圆点时吃触摸**（可移动开）；其余透传 |
| 控制球 / 面板 | `TYPE_APPLICATION_OVERLAY`，小 | 只占小球区域，不抢焦点 |
| 脚本列表浮层 | `TYPE_APPLICATION_OVERLAY`，90%×70% | 浮层内可点，外部透传 |
| 编辑器浮层 | Dialog Activity，90%×70% | 对话框内可点 |

### 4.2 z 序（高 → 低，更新）

```
录制浮层  >  取坐标浮层  >  坐标标记层  >  控制球面板  >  脚本列表浮层  >  编辑器浮层(Dialog)  >  底层 App
```

> 标记层放在控制球之上：标记层对非命中区域 `return false` 透传，控制球仍可点；同时标记点不会被控制球遮挡（点通常不在角落）。

### 4.3 互斥规则（更新 M5 §3.3）

| 打开 | 同时处理 | 理由 |
|---|---|---|
| **编辑器浮层** | **隐藏全局坐标标记层**（避免与编辑器迷你屏重复绘制） | 编辑器有自己的 `CoordinateVisualizer` 迷你屏；全局层叠上去既重复又挡编辑 |
| **录制 / 取坐标** | 隐藏标记层；取坐标时若可移动开着则临时关可移动（§3.4） | 全屏吃触摸，任何可交互层都抢事件 |
| **标记层**（显示开） | 控制球可保持（标记层透传，球仍可点）；列表/编辑器打开时标记层隐藏 | 标记层是常驻参考叠加，不与入口浮层共存 |
| 控制球展开面板 | 不关标记层 | 面板最小，仅自身状态 |

### 4.4 编辑器内是否显示全局标记层

**建议：编辑器打开时隐藏全局标记层**（§4.3）。理由：编辑器已有 `CoordinateVisualizer` 迷你屏展示同口径坐标，全局层重复且会盖住编辑器操作区；关闭全局层后由编辑器迷你屏承担「看坐标」职责，拖动改坐标仍走编辑器内编辑。

## 8. 设计权衡小结（给 fixer 的决策依据）

1. **面板宽度 148dp 而非 108/120**：用户提示的窄档按「三键」估，本方案因新增第 4 颗坐标键重估为 148（4×36+4 边距），比 M5 仍收窄 8%，且靶面 36dp 是实操舒适下限。
2. **坐标开关并入面板而非长按球**：长按球已被「展开面板」占用，并入面板最顺、几乎不增宽。
3. **标记层自带工具条而非回球开关**：坐标两开关与层强相关，层上随手可调；控制球可能被收起遮挡。
4. **可移动 vs 取坐标互斥**：取坐标时临时关可移动（保留显示），避免两个改坐标面抢触摸且用户困惑。
5. **延时占序号不画点**：保证圆点数字与编辑器卡片一一对应，拖动时不会错位。
6. **只动单指**：拖动 = 精确改某点，群组平移留待后续。
7. **标记层透传**：`FLAG_NOT_FOCUSABLE` + 非命中 `return false`，底层 App 平时完全可操作，控制球仍可点。
